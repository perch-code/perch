The inbox

Read GitHub notifications, set a reminder, or clear finished work from your inbox.

On this page

When the inbox refreshes

Perch shows your GitHub notifications in the same order GitHub returns them. It caches them so the inbox opens immediately. Read threads stay in the list alongside unread ones. If the cache cannot be updated, you still see the latest list with your saved Done and Snooze choices applied.

Perch checks for updates in the background at the interval GitHub requests (X-Poll-Interval). It fetches every page at startup and on the first poll after 15 minutes. Between full checks, it uses the first page’s ETag to see whether to fetch the list again. Reading or clearing an older thread on github.com can take until the next full check to appear here. If you sign in after opening Perch, the next poll picks up your token.

New notifications wait behind Refresh so the list stays still while you read. Click it to show the new order. Read indicators update immediately. If the open item changes, Perch offers to refresh its discussion. CI results update automatically when you’re viewing the same commit GitHub checked.

Read state, Done, and snoozing

  • Read. Opening an issue or PR marks its GitHub thread read, whether you open it from Inbox, Worktrees, or Browse. For an unread thread, Perch scrolls to the latest comment or event covered by the notification and briefly highlights it. It waits a few seconds for fresh activity and opens a resolved thread if needed. Scroll yourself to keep your place. Read threads reopen where you left them.
  • Mark Unread adds a reminder in Perch. Open the item to clear it. GitHub’s API cannot mark a thread unread. Perch remembers a read for that version of the thread even if GitHub still reports it unread. New unread activity takes precedence.
  • Done clears the notification on GitHub and in Perch. New unread activity brings it back. Your own comments or updates you’ve already read leave it under Done. Perch checks GitHub before clearing the thread and tells you if a newer unread update arrived. A comment that lands between that check and GitHub accepting Done can still be cleared.
  • Unsubscribe clears the notification and tells GitHub to ignore future activity on that thread.
  • When you merge or close a PR, or close an issue, Perch waits a minute for GitHub’s close notification and marks the thread Done if there’s nothing newer. It treats activity inside that minute as part of the close. A later unread comment brings it back. Items someone else closes stay in your inbox.
  • View › Done shows threads cleared in Perch that GitHub still lists. Move to Inbox restores one in Perch. GitHub’s API cannot undo Done. A restored item stays until a later merge or close qualifies it for Done again.
  • Snooze hides a thread until the time you choose. Later today means 6 PM. Tomorrow, later this week, this weekend, and next week use 8 AM. New unread activity wakes it early. Otherwise it returns with the same read state. Find it under View › Snoozed and use Move to Inbox to wake it yourself. Snoozing affects Perch only.
  • State › Merged or Closed shows finished issues and PRs. Perch counts unknown states, releases, and CI runs as open.
  • Mark N Done clears the threads in the current view. Perch checks each one for newer unread activity, skips those with updates, and reports failures together. Filter to Merged or Closed first to clear only finished work. In Done and Snoozed, the action is Move N to Inbox.
  • Issues and pull requests open in Perch. Other notification types open on GitHub.

The sidebar's filter menus

Each sidebar tab has a filter menu. Choose a view first, then narrow or sort the list. The filter button lights up when you change a default. The search box names the view it searches.

  • Inbox shows active, snoozed, or done notifications. Narrow by GitHub’s notification reason (review requested, yours, assigned, or mentioned), repository, state, or unread status. Yours also includes items you opened. Sort newest or oldest first.
  • Worktrees shows your worktrees. Recent shows everything you opened. Filter either view by repository, state, or unread status. Each remembers its own sort order (last activity, last opened, or created).
  • Browse searches GitHub for items you need to review, own, were assigned, or were mentioned in. Pick All to search the selected repository or every configured GitHub repository. The repository menu also includes repositories known from Worktrees or Inbox. Sort by last activity or creation date.

Choosing a repository filters all three tabs. Each tab also lets you choose Any, Open, or Merged or Closed. Inbox and Worktrees start on Any. Browse starts on Open.

GitHub’s notification API can include Done history without saying which threads are in the web inbox. Changes you make under Done on github.com may differ from what Perch shows.

Clearing a notification keeps the item, its worktree, and its local conversation.

Finished runs on your own work

When an agent finishes an Ask, Work, or review run on a worktree without a pull request, Perch adds a local notification. The row names the repository, branch, and result, such as Claude · Work · 3 files or Review · 2 findings. Failures use the error color. Perch skips runs you were watching in the foreground, canceled runs, runs interrupted when you quit, and sessions started outside Perch.

Each worktree gets one inbox row for its most recent result. Open the item to mark it read, choose Mark Unread for a reminder, or choose Done to hide it until another run finishes. Look under View › Inbox with Yours or All selected. Local rows appear in time order alongside GitHub notifications and have no Snooze option.

Once the worktree has a pull request, its local row disappears. GitHub supplies its inbox notifications from then on. Perch still shows a notice when a run finishes.

Perch fetches a pull request or issue when you open a notification or open the item by repository and number. For agents, you can also enable GitHub history sync per repository.
