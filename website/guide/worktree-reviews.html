Field guide / Review a change

Review a worktree with agents

Choose which agents should read the diff. Check their findings and edit the draft comments before you send a review to GitHub.

On this page
  • Choose your reviewers
  • Choose what to review
  • Reopen or repeat a review
  • Check drafts before posting

Choose your reviewers

Open Review in the top bar. Choose Settings, select the agents you want, and pick a model and effort for each. If an agent is unavailable, the menu explains why. Click Run to start the selected agents.

On a pull request, the same menu holds your drafts, summary, and verdict. Opening reviewer settings collapses your review. Click Open to return to it. The toolbar button shows progress during a run and counts drafts awaiting your review. On a worktree without a PR, the menu contains just the agent settings.

Choose what to review

Each selected agent reviews the same diff. It starts at the last commit the branch shares with the base branch and ends at the version you choose. You can review a worktree Perch created or one you registered, with or without a PR. In Changes, choose where the comparison ends.

  • Last commit reviews through HEAD and leaves out uncommitted files.
  • Working tree includes staged, unstaged, and untracked files. Perch takes a temporary snapshot without changing your branch, files, or Git index.

Perch selects Working tree when the Files view shows uncommitted changes, or when a branch has uncommitted work and no new commits. Otherwise it selects Last commit. There’s no staged-only, single-commit, or incremental review. If the diff is empty, Perch records that and skips the agent run.

Working-tree findings appear beside matching lines in Uncommitted and Branch while the checkout is still on the commit you reviewed. For new lines, the file must still match the snapshot. For old lines, the diff must start at the same merge base. You can read every finding in Conversation.

Use the instructions box to narrow the reviewers’ attention, for example “Review rfcs/multi_get.md only.” The selected diff stays the same. Claude receives the instructions with /code-review. Codex receives them separately because --base does not accept a custom prompt. The review history shows the instructions, and Retry uses them again.

For a PR, Perch also saves the discussion in ~/.perch/context/review-<id>/. It asks reviewers to skip problems already raised in unresolved threads and to flag requested changes that are still missing, naming the person who asked.

Reopen or repeat a review

Perch saves a read-only copy of the diff, commits, and files used for each review. You can reopen the exact lines a reviewer saw after the branch moves or an external worktree is deleted. Opening an old review leaves your current checkout alone.

Claude Code (2.1.223+) and Codex (0.155.1+) use their own review commands, /code-review and codex exec review. Claude’s hosted ultra review mode is unavailable in Perch. Gemini (Antigravity CLI 1.5.5+) and OpenCode (2.3.0+) use Perch’s review instructions. OpenCode reads the saved diff with file tools and no shell. The menu explains why a missing or incompatible CLI cannot run.

Retry runs the same review against the saved snapshot with the same settings. Review latest takes a new snapshot of the branch. When a reviewer finds the same problem again, Perch keeps the discussion in one thread. History includes each attempt, including failures and reviews that found nothing.

Check drafts before posting

On an open PR, findings on lines GitHub accepts become draft comments. Read, edit, or delete them before submitting your review. The card shows the reviewer and severity. Deleting a draft dismisses the finding. Dismissing a finding or marking it as a duplicate removes its draft.

A draft needs a line in the PR diff (a changed line or one of its three context lines), the same head commit, and the same merge base as GitHub. Other findings stay in Perch, including every finding on a worktree without an open PR. See Posting for how drafts reach GitHub.

You decide when to run a review and which findings to post. An agent review leaves your files and GitHub threads as they are. Follow-up questions stay in Perch until you post them.
