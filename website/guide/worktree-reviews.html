Field guide / Review a change

Agent reviews of a worktree

Run Claude Code and Codex against an immutable branch or working-tree snapshot and turn findings into review drafts.

On this page
  • The Review popover
  • Diff scopes and instructions
  • Immutable snapshots and reconciling findings

The Review popover

Review in the bar opens one popover for the whole review. On top are the agents: on a pull request, one line naming the reviewers the next run starts, with Run, and Settings to choose them, the range and the instructions. Each reviewer is one line: a box to take it or leave it, its name, then its model and effort side by side; one that cannot run says why under its name. Under them is your own review for GitHub: the drafts, a summary, and a verdict to send them with. Unfolding the settings folds your review to a line, and Open brings it back. A worktree without a pull request has only the agents, their settings showing. The button is dark while there is a pull request to review, counts your drafts, and says how far a running review has got.

Diff scopes and instructions

Running the agents starts Claude Code and/or Codex's native review workflow against the branch diff from the selected base's merge base to the head. It works for Perch-managed and registered external worktrees, with or without a pull request. Changes in the settings reads head → base, as a review's history does. The head says where the range ends: Last commit is HEAD, and Working tree adds the uncommitted work, staged, unstaged and untracked files alike, as a commit Perch makes over HEAD without touching the worktree, its index or its refs. Head starts on Working tree when the worktree is dirty and the branch has no commits yet, or the Files view shows an uncommitted scope; otherwise on Last commit, and under a dirty worktree's range Perch notes Uncommitted work is left out. Staged-only, individual-commit, and incremental-only review scopes are not supported. If the diff is empty, Perch records that result without launching an agent.

Findings from a review of the working tree show in the Files view under Uncommitted and Branch while the checkout is still on the commit the work sat on, each where its lines read the same as what was reviewed: on the new side, in a file unchanged since; on the old side, when the view diffs from the review's merge base. The rest stay in Conversation.

The instructions box in the settings tells the reviewers what to focus on, such as "review rfcs/multi_get.md only" on a branch that also carries a prototype. The range reviewed stays the same: Claude reads the instructions after the range in its /code-review argument, and Codex, which refuses a custom prompt beside --base, reads them as developer instructions. A review keeps its instructions, so Retry uses them again and its history card shows them.

A review of a pull request also reads its discussion. When the snapshot is taken, Perch writes the discussion to ~/.perch/context/review-<id>/ in the same shape a question gets it, and tells each reviewer, ahead of the requester's instructions, where it is and what to do with it: not to report a problem a reviewer already raised in an unresolved thread, and to report a change a reviewer asked for that the range does not make, naming who asked. A review of a worktree with no pull request has no discussion to read.

Immutable snapshots and reconciling findings

Every review uses a clean, read-only, immutable snapshot in Perch-owned storage. Perch retains its exact diff, manifest, commits, and anchored blobs so history remains readable after the branch moves or an external checkout is deleted. Opening a historical review never changes the current worktree.

Perch currently supports Codex CLI 0.155.1 or newer through codex exec review and Claude Code 2.1.223 or newer through /code-review, when the installed CLI advertises the required local, noninteractive options. Missing, older, or incompatible CLIs are shown as unavailable with a reason; Perch does not fall back to a generic review prompt. Review mode excludes Claude's hosted ultra mode and never enables fix, comment, or permission-bypass options.

Findings are durable local discussions, separate from the attempts that found them. Repeat reviews preserve every group, attempt, observation, failure, and valid zero-finding result while reconciling the same problem back to its existing thread. Retry creates another attempt with the original snapshot and settings. Review latest creates a new group and immutable snapshot from the branch's current state.

Publishing findings as GitHub drafts

On an open pull request, a new finding on lines of its diff arrives as your draft on those lines, in place of the reviewer's message. It is a draft like one you write (see Posting): you edit or delete it, and it posts only when you submit the review. The card above it still gives the severity and the reviewer. Deleting the draft dismisses the finding, and dismissing the finding or linking it as a duplicate deletes the draft. GitHub takes a review comment only on a line its diff shows, a changed line or one of the three around it, so this needs the review to be of what GitHub has: the pull request's head, diffed from the same merge base. Any other finding stays in Perch as the reviewer's message, as does every finding on a worktree without an open pull request.

Follow-ups stay local to Perch unless you post one yourself. Reviews do not resolve threads on GitHub, modify code, run automatically after a push, or use a hosted review service.
