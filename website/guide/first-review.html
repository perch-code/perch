Field guide / Review a change

Review your first pull request

Trace a changed symbol through the codebase, ask an agent about it privately, and submit your review.

Open a pull request

Pick a pull request under Inbox in the sidebar. If your inbox has none waiting yet, switch the sidebar to Browse (Cmd-4) with your repository selected to see open pull requests, or press Cmd-O to open any pull request by URL or number (see The inbox).

Items open on Conversation: the description, timeline events, and review threads in chronological order. Read the description and latest discussion, and pick a question that depends on what the surrounding code does.

Switch to Code

Press Cmd-Shift-2 (Ctrl-Shift-2 on Linux), or click Code at the center of the top bar. Code opens the pull request's checkout with the changed-files drawer on the right. Open a file from the tree, or press Cmd-P to jump to any file on the branch, changed or not.

Follow a symbol

Hover any identifier for its signature and doc comment, then navigate with the shortcuts you already know from VS Code:

ActionKey
Go to DefinitionCmd-click or F12
Go to ImplementationsCmd-F12
Find All ReferencesShift-F12
Show Call HierarchyShift-Alt-H
Back, ForwardCtrl--, Ctrl-Shift--

A single match opens right away; multiple matches open a panel under the editor. Definitions inside a dependency or the standard library open in a read-only tab badged with their crate or package, such as tokio 1.40.0. See Code navigation for scopes, split diffs, and clickable code links.

If nothing opensCheck the status bar: if a language server is missing or waiting for workspace trust (such as rust-analyzer on an external PR), triggering Go to Definition offers to install or Trust and start it.

Ask an agent on the line (optional)

With a supported coding-agent CLI signed in (Claude Code, Codex, Antigravity, or OpenCode), click + in the gutter beside a line—or click Ask about this on an existing GitHub comment—to open the composer. Choose a model from the dropdown, then type your question. You can bring multiple models into the same thread to cross-check an answer; see Agent sandbox and approvals.

Post your review

To leave feedback for the author, switch the composer's destination to GitHub. Line comments save locally with a Draft pill, survive restarts and offline work, and stay hidden from github.com until you submit.

When you are ready, click Review in the top bar, choose your verdict, and submit—publishing all of your drafts in one batch. See Posting and drafts for inline suggestions and replies, or Agent reviews of a worktree to run automated bug checks first.
