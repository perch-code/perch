Opening a pull request

Fill the title and description from templates or an agent, push with your own git credentials, and turn the worktree into a PR.

On this page
  • Filling the pull request form
  • Pushing and creating on GitHub
  • Pushing new commits to an open PR

Filling the pull request form

A worktree of your own with commits past its base has a Pull request line at the foot of Conversation, where a pull request has its checks and Merge: Pull request · 3 commits ahead of main. Open pull request… unfolds it into a form:

  • Title, filled in from the commit's subject when there is one commit, else from the item's name.
  • Description, a composer's box going to GitHub, so @ offers people and files as code spans. Filled in from the repository's pull request template (.github/, the root, then docs/), else the one commit's body, else the commits' subjects as a list. A branch Start work cut from an issue or a pull request ends it with Closes #<n>, as does a description the agent writes.
  • Base, the branch it goes into: the one the branch was cut from, or any branch the repository has on GitHub.
  • Draft, off.
  • Write with Claude, or Codex, whichever the composer last used: the agent reads the branch under Ask's rules and writes a title and description into the form. Text you typed isn't written over; the form asks first. Stop ends it. The run isn't kept with the item's runs.

Pushing and creating on GitHub

The form fills itself once, and keeps what you typed until Perch quits, whether it's folded or another item is open. Cmd-Enter in the description, or Open pull request, sends it:

  1. GitHub is asked whether the branch has a pull request open already, as one opened on github.com that no poll has found yet. If it has, the row takes that one, and nothing is pushed or created.
  2. The branch is pushed, never with force. A worktree of one of your clones pushes with your own git credentials and SSH key, never Perch's token, and the branch then tracks what it was pushed to. A worktree of Perch's own clone pushes with Perch's token.
  3. The pull request is created, and the row becomes it in place, with its threads and runs. The open item turns into the pull request.

Uncommitted files are named and left out. A Work run in the worktree, a worktree switched to another branch, or an empty title keep the button off. A push the remote refuses, because its branch has commits yours doesn't, says to pull or rebase in a terminal. A push your credentials can't make, such as with an SSH key that wants a passphrase, says to push from a terminal; after that, Open pull request skips the push. Neither agent can push or open a pull request: Perch does it when you press the button.

Pushing new commits to an open PR

On a pull request of yours whose worktree is ahead of it and not behind, the Branch row has Push beside 3 unpushed. It pushes the same way, and the pull request is fetched again, so Submit review and Merge come back. The merge box at the foot of Conversation has it too, as Push 3 commits where Merge would be. Behind or diverged has no button, since that push would need force.
